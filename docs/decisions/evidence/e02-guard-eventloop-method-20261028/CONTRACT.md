## Recommendation and alternatives

Prefer one finite owned Python guard interpreter per fixture Node process, using the existing pinned loader/Python runtime and importing the exact byte-identical `lease_guard.py`. Each request invokes the original `Lease.check()` afresh. A process exists only within its owning Node process's original command/service lifetime and original root1800s lease. The serve process and each separate short controller process have distinct owned helper identities; they never share decisions or use an external daemon.

A nonblocking one-shot Python subprocess per original check is a simpler fallback: it retains cold startup cost, does not establish the retained `Lease.previous` continuity of a persistent interpreter, and may still exhaust the unchanged10s/55s budgets under a burst. It must be evaluated honestly if chosen; moving the same cold process calls to an awaited worker does not demonstrate sufficient throughput. A Node worker that performs the existing synchronous call can move the blocking work away from the networking loop but retains the same startup/serialization costs and adds another ownership/cancellation layer. Neither is rejected as unsafe in principle; the persistent interpreter is recommended for the bounded experiment because it can remove repeated interpreter initialization while retaining the original fresh authorization function.

Do not use cached authorization, shared permits, periodic OK flags, a reusable success response, a longer timeout, a reissued lease or a reset clock history. This is an execution-method change, not new cryptography, a new authority model or a production service.

## Closed finite helper transport

Use only the exact owned child's stdin/stdout; no listening socket, network endpoint, reusable broker, installation, shared service or caller-selected process target. Proposed protocol operations are `CHECK` and orderly `CLOSE` only. CHECK metadata contains a fixed schema/version, fresh helper instance ID, run ID, original lease SHA, monotonic request sequence, fixed guard-point label and immutable effect-context digest. No action payload or path can be requested. The worker must reject duplicate, decreasing, foreign, out-of-order or unknown requests. Sequence exhaustion fails rather than wrapping or starting a new helper.

Use strict UTF-8 newline frames with a closed schema and a maximum1024-byte request/2048-byte response. Register exact integer/string domains and reject duplicate keys, nonfinite values and extra fields. A successful response binds the exact request bytes/hash, instance/run/lease/sequence and an actual fresh check result. Exact clock samples are retained without conversion to rounded JavaScript nanosecond Numbers. A response is a one-use result for that particular continuation, never a permit or a freshness cache. READY proves only startup identity, never authorization; the first required guard check still runs.

There is at most one in-flight request per helper. The proposed guarded-continuation queue is bounded at64 entries and aggregate queued raw payload is at most the original aggregate capture ceiling. A smaller reviewed bound is acceptable; no bound may be silently enlarged. Overflow is a terminal unqualified failure, never frame dropping, check coalescing, latest-wins replacement or automatic retry. Every original watchdog tick submits its fresh check or fails the closed bound; it is not skipped because a prior tick is pending.

Each check has a nonrenewable5s decision deadline measured from original submission, including queue wait, helper startup where applicable, serialization, fresh check and response validation. A queued request does not receive another5s when sent. Late success, timeout, partial/extra stdout, stderr on a success path, mismatch, unexpected EOF or child death is negative. No helper restart or replay occurs within the window. Both normal helper startup and its first required check must fit the same first5s decision bound, not two consecutive5s allowances.

EOF after an explicit orderly CLOSE is permitted only with no pending request, no remaining continuation and no future use by that owner. This is required for controller processes to exit without revoking a separate healthy service helper. Unexpected EOF, malformed transport or infrastructure failure is a first fault. The service locally fences all further actions immediately; use original `Lease.revoke` when an alive helper can perform sticky revocation, and preserve the existing host guard's child-failure/cleanup propagation. Do not claim that a dead helper wrote a revocation file. Record observed revocation/exit/cleanup facts honestly.

Cancellation must stop acceptance of new requests, reject queued/in-flight continuations, close only owned endpoints, terminate only the exact owned child when necessary and retain actual EOF/exit/close/reap evidence under a reviewed finite cleanup budget. Any TERM/KILL/reap reserve is contained inside existing command/lease/cleanup clocks; it does not extend the5s decision deadline,10s query,3s handshake,55s command or1800s lease. No detached orphan, shell, unknown process group or reused PID may be targeted. Node child-event observations must not be labelled as Python Popen/waitpid attestation.

## Nonblocking scheduler and terminal fences

Simply changing `check()` to return a Promise is insufficient. An await permits subscription, generation, attempt, socket and terminal state to change. A single lock around the entire publish operation is also wrong: publish awaits an exchange whose reply callbacks need that lock, producing a deadlock.

Serialize only short guarded continuations that perform an original fresh check followed by their original synchronous state/effect segment. The event loop stays free while waiting for the owned helper. The successful response is validated and consumed exactly once, the current terminal epoch and socket/generation/attempt bindings are rechecked, and the effect runs in that same continuation without another asynchronous yield. Release the short executor before waiting for network replies, delivery, control responses or another guarded continuation. High-level prepare/publish/exchange orchestration may await many such segments; it never holds the executor across those waits.

Capture immutable callback bytes and bounded context at enqueue time. Before state changes or sends after an await, require the exact current connection/subscription generation, stage/attempt epoch, publication-window state, buffer hash and applicable original effect predicates. A changed context rejects or cancels that continuation; no old delivery, subscription or send completion is donated to a newer stage. All original checks keep their original positions relative to the effects they protect. Any newly needed context fence supplements those assertions.

Socket errors/closes, query/handshake deadlines, helper death, cancellation and capture poisoning must establish the terminal fence immediately outside the work queue. They cannot wait behind guard RPCs. Claim the first fault once, invalidate pending epochs, cancel all continuations and close exact owned sockets. Late responses/callbacks cannot send, mutate protocol state, advance a stage, clear the first fault or append success evidence. Ownership cleanup and its separately identified terminal retention remain permitted; do not hide late protocol writes as cleanup. Catch async rejections at the callback boundary so no rejection escapes to an unobserved Promise.

Keep the current terminal error precedence: an incoming socket error remains primary over a later guard/observation/retention failure; secondary errors are retained without preventing owned cleanup. Phase/capture write failure poisons the original shared budget and fences actions. There is no retry of a short/failed proof write. A timer does not need another authorization check before it can deny/terminate.

The original check-to-effect handoff is not an atomic cross-process authorization transaction. This proposal makes no stronger atomic claim. It requires one fresh core check for each effect, immediate one-use completion, the original parent guards and explicit local terminal/deadline fences. Security review and delayed-response/expiry vectors must confirm that the new asynchronous gap cannot admit a stale queued success. If that cannot be demonstrated under the original trust/clock assumptions, this method is not ready for implementation/runtime; do not invent a reusable permit-age allowance.
